# Salt.Box Security Policy

## Reporting a Vulnerability

If you believe you've found a security vulnerability in any Salt.Box
repository, please report it privately – **NOT** as a public GitHub issue.

- **Preferred channel:** use [GitHub's Private Vulnerability
Reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing/privately-reporting-a-security-vulnerability)
on the affected repository
- **Alternative channel:** email **security@saltbox.pro**

## What to Include

- A descriptive subject line
- Steps to reproduce (PoC scripts, screenshots, or logs help a lot)
- The affected repository/component and version
- The impact of the vulnerability and, if known, its attack surface
- Any third-party dependencies involved

## Our Process

1. A report is acknowledged and assigned an owner on the Salt.Box team
2. The issue is reproduced and its affected components/versions confirmed
3. A fix is prepared and released for supported versions
4. Once a fix is available, we publish an advisory with upgrade instructions
   via the affected GitHub/GitLab repository and/or [saltbox.pro/blog](https://saltbox.pro/blog)

## Scope

This policy covers all repositories under the Salt.Box GitHub organization
and their GitLab counterparts at [dev.saltbox.pro](https://dev.saltbox.pro/)

## Please Don't

- File public GitHub issues for security vulnerabilities
- Disclose a vulnerability publicly before a fix has shipped
